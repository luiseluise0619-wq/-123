# 운영 보안 확인 — 2026-09-11

현재 코드 검증은 무침해 보증이나 외부 보안 인증이 아닙니다. 실제 운영 인프라와 계정에는 접속하지 않았습니다.

## 반영한 방어

- 공개 Node API를 명시적으로 제한하고 정적 파일 노출 경계를 검사합니다.
- 요청 크기·시간·빈도·동시성 제한, 입력 검증, CSP를 유지합니다.
- 외부 오류 message/stack은 이메일·설문·키가 포함될 수 있어 로그에 남기지 않습니다. 엔드포인트와 제한된 오류 종류만 기록하며 회귀 테스트를 추가했습니다.
- push/PR마다 HTML·데이터·체크섬·전체 테스트·운영 패키지 검사를 실행하는 CI를 추가했습니다. 실행 액션은 확인한 commit SHA로 고정하고 저장소 읽기 권한만 부여합니다. 브랜치 보호의 필수 검사 설정은 별도입니다.

## 회사 운영 전에 실제 확인할 항목

- GitHub·호스팅·메일·DB의 회사 소유권, 다중 인증, 최소 권한, 퇴사자 권한 회수.
- 개인 API 키를 회사 키로 교체하고 서비스별 승인·한도 확인.
- TLS, 방화벽, 프록시 IP 신뢰 설정, 서버 패치·백업 복구·로그 접근 권한.
- 메일 수신자 확인과 자동 발송 남용 방어. 현재 메일은 설정 전까지 비활성입니다.
- 향후 고객 DB에 인증된 관리자만 접근하도록 하고, 내보내기 권한·보유 기간·삭제·동의 기록을 정의할 것. 현재 Node 서비스에는 고객 DB/관리자 조회 기능이 없습니다.

실운영 접근 권한이나 키를 채팅에 붙여넣지 말고 서비스의 Secrets/환경변수에 설정합니다.
