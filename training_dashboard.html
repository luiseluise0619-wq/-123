안전 경계코드를 실행하지 않고, 외부 대상에 접속하거나 익스플로잇을 전달하지 않습니다. 결과에는 원본·패치 코드가 보존되지 않습니다.

분석 요약

숫자는 최신 저장소 기반 학습 및 이번 레드팀·블루팀 훈련에서 계산됩니다.

레드팀·블루팀 라운드

각 라운드의 모델 위험 확률, 심판 탐지, 블루팀 패치와 재스캔 검증 결과입니다.

새 레드팀 시나리오를 안전하게 추가하는 방법

새 시나리오는 외부 공격 기능이 아니라, 정적 분석과 방어 규칙을 검증할 수 있는 로컬 교육용 코드 문자열이어야 합니다.

  1. security_engine/red_blue_arena.py의 SAFE_TRAINING_SCENARIOS에 TrainingScenario를 추가합니다.
  2. 고유한 scenario_id, 분류명, 한 줄 설명, 실행하지 않을 최소 Python 예제를 정의합니다.
  3. Bandit이 실제로 식별하는지 확인하고, 지원되는 결정적 패치가 없는 경우에는 사람 검토 항목으로 남깁니다.
  4. python3 -m unittest discover -s tests -v를 실행해 심판 재스캔과 안전 경계를 검증합니다.
  5. 실제 호스트·네트워크 대상·자격 증명·동작하는 익스플로잇·임의 페이로드는 추가하지 않습니다.

안전한 시나리오 형식

아래처럼 최소한의 비실행 소스만 사용합니다. 모델 학습에 쓰는 저장소 코드 역시 읽기·AST 추출·정적 라벨링만 수행합니다.

TrainingScenario(
  scenario_id="weak-hash-example",
  category="cryptography",
  description="Weak hash detection exercise.",
  source_code=(
    "import hashlib\\n\\n"
    "def digest(data):\\n"
    "    return hashlib.md5(data).hexdigest()\\n"
  ),
)

지원 패치가 필요하면 security_ai_core.py에 작은 결정적 변환을 추가하고, 반드시 Bandit 재스캔 테스트를 함께 추가하세요.

“저장소로 훈련 실행”을 누르면 GitHub 저장소의 Python 파일을 정적으로 라벨링하고, 자체 모델 학습·레드팀·블루팀 결과를 이 화면에 표시합니다.
이 화면은 로컬 개발용입니다. 현재의 요청 헤더는 프로덕션 인증이 아니므로, 공개 배포 전에는 검증된 인증·권한부여·속도 제한을 적용해야 합니다.
