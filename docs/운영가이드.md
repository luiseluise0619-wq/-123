# 대시보드 운영 가이드 (초보자용)

이 문서 하나로 **이 사이트가 무엇이고, 어떤 데이터가 어디에 들어가서 무슨 역할을 하며,
어떤 원리로 돌아가는지** 처음 보는 사람도 이해할 수 있게 정리했습니다.
그리고 실무(실행·키·문제해결)까지 다룹니다.

---

## 0. 이 프로젝트가 뭐예요? (1분 요약)

서울에서 **어디에 어떤 장사를 하면 좋을지**를 공개 통계로 보여주는 웹 지도입니다.
화면은 두 개입니다.

| 화면 | 파일 | 무엇 | 지도 종류 |
|---|---|---|---|
| **개요 지도** | `index.html` | 자치구 25개를 색으로 비교(폐업추세·유동인구·매출 등) | 직접 그린 SVG 지도 |
| **건물 지도** | `building.html` | 실제 지도 위에서 역·상권·업소를 보고, **핀 찍으면 그 지점 브리핑** | 카카오 실지도 |

둘 다 **정적 웹사이트**입니다. 즉, 서버가 매번 계산해서 주는 게 아니라 **미리 만들어 둔 파일**을
그대로 보여줍니다. 그래서 "데이터를 어떻게 미리 만들어 두느냐"가 이 프로젝트의 핵심입니다.

## 1. 큰 그림 — 데이터가 화면까지 오는 길

### 먼저, 왜 복잡할까?

브라우저(사용자 화면)는 **공공데이터 API를 직접 못 부릅니다.**
- API 키가 노출되면 남이 훔쳐 씁니다.
- 브라우저 보안(CORS) 때문에 막힙니다.
- 호출 횟수 제한도 있습니다.

그래서 **두 가지 우회로**를 씁니다.

### 방법 A — 배치 (미리 받아서 파일로 저장) : 대부분의 데이터

```
 ┌─ GitHub Actions (자동 로봇, 주간 or 수동) ─────────────┐
 │  1. 서울/정부 공개 API 호출 (서버에서, 비밀키 사용)      │
 │  2. 받은 응답을 frontend/*.json 파일로 저장             │
 │  3. 저장소(git)에 커밋                                  │
 └───────────────────────────┬───────────────────────────┘
                             ▼
        Vercel 이 그 파일을 인터넷에 그대로 서빙
                             ▼
     index.html / building.html 이 파일을 읽어서 지도에 그림
```

느리게 변하는 데이터(분기·연 단위)에 적합합니다. "로봇이 대신 받아 파일로 굳혀둔다"고 보면 됩니다.

### 방법 B — 실시간 프록시 (클릭할 때마다 호출) : 검색·주소·경쟁점포

```
 브라우저(핀 클릭) → /api/kakao (작은 서버 함수) → 카카오 REST 실시간 호출 → 결과 반환
```

사용자가 클릭하는 지점은 무한히 많아 미리 파일로 못 만듭니다. 그래서 **그 순간에** 물어봅니다.
`/api/kakao.js`, `/api/chat.js` 가 이런 "작은 서버 함수(서버리스)"입니다.

> **한 줄 정리**: 천천히 바뀌는 건 로봇이 미리 파일로(A), 그때그때 필요한 건 작은 서버가 실시간(B).

## 2. 데이터 사전 — 어떤 데이터가 어디에 들어갔나

각 파일이 **① 무슨 데이터 ② 어느 화면·기능에 보이나 ③ 누가 만드나** 순으로 정리했습니다.

### (1) 지도 뼈대 — 경계선
| 파일 | 무슨 데이터 | 어디에 보이나 |
|---|---|---|
| `seoul_gu.geojson` | 자치구 25개 경계 좌표 | 두 지도 모두의 자치구 윤곽선 |
| `seoul_dong.geojson` | 행정동 경계 좌표 | 개요 지도의 동 단위 드릴다운 |

> 이건 거의 안 바뀌므로 한 번 만들어두면 끝(수집 대상 아님).

### (2) 개요 지도(`index.html`)에 들어가는 데이터
개요 지도의 **기본 데이터는 `data-bundle.js`** 에 통째로 들어 있습니다(업종·자치구 기본 통계).
그 위에 아래 파일들이 **얹혀서(overlay)** 색칠 지표가 됩니다.

| 파일 | 무슨 데이터 | 개요 지도에서의 역할 |
|---|---|---|
| `data-bundle.js` | 업종별 원가·투자·매출분포, 자치구 폐업추세·정류소 | 화면의 뼈대 데이터(항상 로드) |
| `livepop_gu.json` | 자치구별 유동(생활)인구 | "유동인구" 색칠 지표 |
| `parking_gu.json` | 자치구별 주차장 | "주차" 색칠 지표 |
| `subway_stations.json` | 역별 승하차 + 좌표 | "지하철(역 단위)" 점 지도 |
| `sales_by_industry.json` | 업종별 시간·요일·연령 매출 | 매출 패턴 차트 |
| `stores_by_industry.json` | 업종별 폐업률·프랜차이즈 | 경쟁·위험도 |
| `repop.json` | 상주(거주)인구 | 배후수요 |
| `workpop.json` | 직장인구 | 출근수요 |
| `income.json` | 소득·소비 | 소비력 |
| `sales_forecast.json` | 매출 예측 백테스트 | 예측 지표 |

### (3) 건물 지도(`building.html`)에 들어가는 데이터
| 파일/소스 | 무슨 데이터 | 건물 지도에서의 역할 |
|---|---|---|
| `seoul_gu.geojson` | 자치구 경계 | 배경 경계선 |
| `subway_stations.json` | 역별 승하차+좌표 | **파란 원 마커**(크기=승하차) · 핀 분석의 "주변 역" |
| `trade_zones.json` | 상권 중심좌표+점포수 | **주황 원 마커** · 핀 분석의 "가까운 상권" |
| `livepop_gu.json` | 자치구 유동인구 | 핀 분석의 "유동인구" |
| `/api/kakao` (실시간) | 카카오 검색·주소·카테고리 | 업소 검색 · 주소 변환 · 반경 경쟁점포 |

### (4) 상권 "원천" 데이터 (무거움, 분기 1회)
| 파일 | 무슨 데이터 | 역할 |
|---|---|---|
| `seoul_trdar_dataset.csv` | 서울 전 상권×업종 매출·점포·좌표 | 아래 둘의 **재료**(직접 화면엔 안 씀) |
| `distance_decay.json` | 역과의 거리별 매출 감쇠 분석 | 역세권 프리미엄 분석 |
| `trade_zones.json` | 상권 중심좌표(WGS84 변환) | 건물 지도 상권 마커 |

## 3. 각 데이터는 어떤 원리로 만들어지나 (초보 설명)

- **서울 열린데이터광장 / data.go.kr**: 정부·서울시가 공개하는 통계 API. `SEOUL_API_KEY`,
  `DATA_GO_KR_KEY` 로 인증해 호출합니다. 수집기(`collect_*.py`)가 이걸 불러 JSON 으로 저장합니다.
- **좌표계 변환**: 상권 원천 데이터의 좌표는 `EPSG:5181`(옛 한국 좌표계)입니다. 카카오 지도는
  `WGS84`(위경도)를 쓰므로, `make_trade_zones.py` 가 변환해서 `trade_zones.json` 을 만듭니다.
- **핀 분석의 "주변 역·상권"**: 서버 없이 브라우저가 **직접 계산**합니다. 클릭 지점과 모든 역/상권의
  거리를 재서(하버사인 공식) 가까운 것을 고릅니다. 그래서 이 부분은 키 없이도 즉시 동작합니다.
- **핀 분석의 "경쟁점포·주소"**: 이건 계산이 아니라 카카오에 물어봐야 해서 `/api/kakao` 실시간 호출을
  씁니다(그래서 `KAKAO_REST_KEY` 필요).

## 4. 데이터 갱신 주기 — 언제 무엇을 받아야 하나

| 데이터 묶음 | 원천이 바뀌는 주기 | **권장 실행** |
|---|---|---|
| 유동인구, 지하철 | 일별 | **주간** |
| 주차장 | 수시 | 월간 |
| 매출·점포·소득·상가정보·상주/직장인구 | 분기~연 | 분기 |
| **상권 원천 CSV · 거리감쇠 · 상권 마커** | 분기 | **분기 1회 (느림)** |

> 즉 매주 다 돌릴 필요가 없습니다. **자주 바뀌는 건 유동인구·지하철뿐**입니다.

## 5. "실행이 맨날 느린" 이유와 해결 (중요)

느림의 주범은 딱 하나 — **상권 전량 빌드(`build_seoul_dataset.py --build`)** 입니다.
서울 전 상권을 페이징으로 긁어 조인하느라 수십 분이 걸립니다. 그런데 이 데이터는 **분기별**이라
매주 돌릴 이유가 없습니다.

### 해결: `heavy` 스위치 (이미 적용됨)

워크플로 실행 시 **`heavy` 체크박스**가 있습니다.

- **체크 해제(기본)** → 무거운 상권 3스텝을 **건너뜀** → 몇 분 내 완료. 주간 자동 실행도 항상 이 모드.
- **체크 ON** → 상권 CSV·거리감쇠·상권마커까지 재생산(수십 분). **분기에 한 번만** 켜세요.

또한 지하철 수집 **직후 "1차 커밋"** 이 있어, 역·자치구 데이터는 무거운 빌드와 무관하게 **먼저**
사이트에 반영됩니다.

## 6. 실행 방법

### 평소(주간, 빠름)
GitHub → **Actions** → **대시보드 자동 갱신** → **Run workflow** → Branch `master`
→ `heavy` **체크 해제** → Run.

### 분기 1회(상권 갱신, 느림)
같은 화면에서 `heavy` **체크 ON** → Run.

> 실행 버튼은 **저장소 관리자 계정만** 누를 수 있습니다.

## 7. 필요한 키 · 환경변수

### GitHub Actions Secrets (배치 수집용)
저장소 → Settings → Secrets and variables → Actions

| 시크릿 | 용도 |
|---|---|
| `SEOUL_API_KEY` | 서울 열린데이터광장 (대부분의 수집기) |
| `DATA_GO_KR_KEY` | data.go.kr (주차장·상가정보) |

### Vercel 환경변수 (실시간 프록시용)
Vercel → 프로젝트 → Settings → Environment Variables

| 변수 | 용도 |
|---|---|
| `KAKAO_REST_KEY` | `/api/kakao` 검색·주소·경쟁점포 (카카오 **REST 키**, 서버 전용 비밀키) |
| `GEMINI_API_KEY` | `/api/chat` AI 상담 |
| `ALLOWED_ORIGIN` | (선택) 프록시 허용 도메인 고정 |

> **키 3종 구분** (헷갈리기 쉬움):
> - **JavaScript 키** → 지도 표시용. 공개돼도 됨(도메인으로 보호). `building.html` 코드에 포함.
> - **REST 키** → 검색·주소용. **비밀**. 코드 금지, `KAKAO_REST_KEY` 환경변수로만.
> - **어드민 키** → 서버 관리용. **절대** 코드/채팅에 넣지 말 것.

## 8. 문제 해결 (트러블슈팅)

| 증상 | 원인 | 조치 |
|---|---|---|
| 건물 지도 "지도를 불러오지 못했어요" | [카카오맵] 사용 설정 OFF / 도메인 미등록 | 카카오 콘솔에서 사용 설정 ON + JavaScript SDK 도메인 등록 |
| 핀 분석 "주소 변환/경쟁점포 실패" | `KAKAO_REST_KEY` 미설정 | Vercel 환경변수 추가 후 재배포 |
| 역/상권 마커가 안 보임 | 해당 JSON 미커밋 | 워크플로 실행(상권은 `heavy` ON) |
| 워크플로가 너무 느림 | 상권 빌드가 켜짐 | `heavy` 체크 해제로 실행 |
| 429 Too Many Request | 카카오 무료 쿼터 소진 | 비즈월렛 연결·유료 설정 또는 다음 날 |
| 수집 한 스텝 실패해도 나머지는 진행됨 | `continue-on-error: true` 설계 | 정상 — 실패 파일만 이전 값 유지 |

## 9. 용어 사전 (초보자용)

- **정적 사이트**: 서버가 계산하지 않고, 미리 만든 파일을 그대로 보여주는 웹사이트. (Vercel)
- **API**: 데이터를 요청하면 돌려주는 창구. 여기선 서울시·정부·카카오의 데이터 창구.
- **배치**: 미리 한꺼번에 받아서 저장해두는 방식(워크플로).
- **서버리스(작은 서버 함수)**: `/api/*.js`. 필요할 때만 잠깐 실행되는 미니 서버. 비밀키를 숨겨서 대신 호출.
- **워크플로 / GitHub Actions**: 정해둔 순서대로 스크립트를 자동 실행하는 로봇. `.github/workflows/`.
- **커밋**: 파일 변경을 저장소에 기록하는 것. 워크플로가 새 데이터를 커밋하면 사이트가 갱신됨.
- **좌표계(EPSG:5181 / WGS84)**: 지도 위 위치를 숫자로 표현하는 규칙. 둘이 달라서 변환이 필요.
- **하버사인**: 위경도 두 점 사이 실제 거리를 구하는 공식(주변 역/상권 계산에 사용).
