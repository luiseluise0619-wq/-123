# 대시보드 데이터 운영 가이드

이 문서는 **어떤 데이터를 언제·어떻게 받아야 하는지**를 정리한 관리자용 설명서입니다.
지도(`index.html`, `building.html`)가 읽는 데이터가 어디서 오고, 무엇을 얼마나 자주 돌려야
하는지, 그리고 "실행이 맨날 느린" 문제를 어떻게 피하는지 다룹니다.

---

## 1. 데이터가 흐르는 두 가지 방식

### A. 배치 — 미리 받아서 파일로 저장 (대부분의 데이터)

```
GitHub Actions 워크플로 (주간 or 수동)
  → 서울 열린데이터광장 / data.go.kr API 호출 (서버에서, 시크릿 키 사용)
  → 응답을 frontend/*.json 파일로 저장
  → 저장소에 커밋 → Vercel 이 정적 파일로 서빙
  → index.html / building.html 이 그 JSON 을 fetch 해서 그림
```

브라우저가 공공 API 를 직접 못 부르기 때문에(키 노출·CORS·호출량 제한),
**미리 받아 파일로 굳혀두고** 프론트는 파일만 읽습니다.
느리게 변하는 데이터(분기·연 단위)라 이 방식이 맞습니다.

### B. 실시간 프록시 — 그때그때 호출 (검색·주소·경쟁점포)

```
브라우저(핀 클릭) → /api/kakao 서버리스 → 카카오 REST 실시간 호출 → 결과 반환
```

사용자가 클릭하는 지점이 무한히 많아 파일로 못 만듭니다. 클릭할 때마다 물어봅니다.
`KAKAO_REST_KEY`(Vercel 환경변수)가 필요하며, 워크플로와 무관합니다.

| 구분 | 대상 | 시점 | 키 위치 |
|---|---|---|---|
| 배치(A) | 역·유동인구·상권·주차·매출·점포 | 주기적(워크플로) | GitHub Actions Secret |
| 실시간(B) | 업소 검색·주소 변환·반경 경쟁점포 | 클릭할 때마다 | Vercel 환경변수 |

## 3. "맨날 느린" 이유와 해결

느림의 주범은 **상권 전량 빌드(`build_seoul_dataset.py --build`)** 단 하나입니다.
서울 전 상권×업종을 페이징으로 긁어 조인하느라 수십 분이 걸립니다.
그런데 이 데이터는 **분기별**이라 매주 돌릴 이유가 없습니다.

### 해결: `heavy` 토글 (이미 적용됨)

워크플로에 `heavy` 입력을 추가해, 느린 상권 3스텝을 **명시적으로 켤 때만** 실행합니다.

- **주간 스케줄 실행** → `heavy` 자동 OFF → 상권 빌드 건너뜀 → **몇 분 내 완료**
  (유동인구·지하철 등 자주 바뀌는 데이터만 갱신, 역 데이터는 1차 커밋으로 먼저 반영)
- **분기 1회 수동 실행** → `heavy` 체크 ON → 상권 CSV·distance_decay·trade_zones 재생산

### 커밋 순서 (역 데이터가 느린 빌드에 안 묶이도록)

지하철 수집(step 14) **직후에 1차 커밋 스텝**이 있어, 역·자치구 데이터는
무거운 상권 빌드와 무관하게 먼저 master 에 반영됩니다. 상권 결과는 heavy 실행의
마지막 커밋에서 반영됩니다.

## 4. 실행 방법

### 평소 (주간, 빠름)
GitHub → **Actions** → **대시보드 자동 갱신** → **Run workflow** → Branch `master`
→ `heavy` **체크 해제** → Run.
(스케줄로도 매주 월요일 자동 실행되며 항상 heavy OFF 입니다.)

### 분기 1회 (상권 데이터 갱신, 느림)
같은 화면에서 `heavy` **체크 ON** → Run. 수십 분 소요.
새 분기 상권·매출이 나온 뒤(보통 분기 시작 후 1~2개월)에만 돌리면 됩니다.

> 관리자 계정만 실행 버튼을 누를 수 있습니다(외부 integration 은 dispatch 불가).

## 5. 필요한 키 · 환경변수

### GitHub Actions Secrets (배치 수집용)
저장소 → Settings → Secrets and variables → Actions

| 시크릿 | 용도 |
|---|---|
| `SEOUL_API_KEY` | 서울 열린데이터광장 (대부분의 수집기) |
| `DATA_GO_KR_KEY` | data.go.kr (주차장·상가정보 등) |

### Vercel 환경변수 (실시간 프록시용)
Vercel → 프로젝트 → Settings → Environment Variables

| 변수 | 용도 |
|---|---|
| `KAKAO_REST_KEY` | `/api/kakao` — 검색·주소변환·경쟁점포 (카카오 REST 키, **서버 전용**) |
| `GEMINI_API_KEY` | `/api/chat` — AI 상담 |
| `ALLOWED_ORIGIN` | (선택) 프록시 허용 도메인 고정 |

> `building.html` 의 카카오 지도용 **JavaScript 키**는 공개용이라 코드에 포함(referer 로 보호).
> REST·어드민 키는 **비밀키** — 코드/커밋에 넣지 말고 위 환경변수로만.

## 6. 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| building.html "지도를 불러오지 못했어요" | 카카오 [카카오맵] 사용 설정 OFF / 도메인 미등록 | 콘솔에서 사용 설정 ON + JavaScript SDK 도메인 등록 |
| 핀 분석에서 "주소 변환/경쟁점포 실패" | `KAKAO_REST_KEY` 미설정 | Vercel 환경변수 추가 후 재배포 |
| 역/상권 마커가 안 보임 | 해당 JSON 미커밋 | 워크플로 실행(상권은 heavy ON) |
| 워크플로가 너무 느림 | 상권 빌드가 켜짐 | `heavy` OFF 로 실행 |
| 429 Too Many Request | 카카오 무료 쿼터 소진 | 비즈월렛 연결·유료 설정 또는 다음 날 |
| 수집 스텝 하나 실패해도 나머지 진행 | `continue-on-error: true` 설계 | 정상 — 실패 파일만 이전 값 유지 |
