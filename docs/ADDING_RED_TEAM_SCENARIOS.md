# 레드팀 교육 시나리오 추가 가이드

AegisAI의 레드팀은 실제 대상에 대한 공격 기능이 아니라, **블루팀의 탐지·수정·재스캔 검증을 훈련하기 위한 로컬 정적 분석 시나리오**입니다. 따라서 새 항목은 외부 시스템, 네트워크 서비스, 자격 증명 또는 동작하는 익스플로잇을 포함해서는 안 됩니다. 시나리오의 목적은 Bandit 심판이 식별 가능한 교육용 코드를 준비하고, 결정적 패치가 가능한 경우에만 블루팀의 수정 결과를 객관적으로 검증하는 것입니다.

> 레드팀 성공은 시나리오가 위험한 코드를 실제로 실행했다는 뜻이 아닙니다. Bandit이 비실행 코드 문자열에서 정적 분석 결과를 반환했다는 뜻입니다. 블루팀 성공은 특정 규칙이 패치 후 재스캔에서 사라졌을 때만 기록됩니다.

## 1. 시나리오 위치와 구조

새 시나리오는 `security_engine/red_blue_arena.py`의 `SAFE_TRAINING_SCENARIOS` 튜플에 `TrainingScenario` 인스턴스로 추가합니다. 각 항목은 고유 식별자, 분류, 교육 목적 설명, 그리고 최소한의 Python 코드 문자열을 가져야 합니다.

| 필드 | 요구 사항 | 예시 |
| --- | --- | --- |
| `scenario_id` | 소문자·하이픈 기반의 고유 ID | `weak-hash-example` |
| `category` | 보안 주제를 설명하는 짧은 분류 | `cryptography` |
| `description` | 공격이 아닌 훈련 목적을 설명 | `Weak hash detection exercise.` |
| `source_code` | 실행하지 않을 짧은 Python 소스 문자열 | 약한 해시 사용 예제 |

```python
TrainingScenario(
    scenario_id="weak-hash-example",
    category="cryptography",
    description="Weak hash detection exercise.",
    source_code=(
        "import hashlib\n\n"
        "def digest(data):\n"
        "    return hashlib.md5(data).hexdigest()\n"
    ),
)
```

## 2. 허용 기준과 금지 기준

새 시나리오는 분석기가 식별할 수 있는 위험한 API 사용 또는 설정을 **최소 코드로 표현**해야 합니다. 테스트의 재현성을 높이기 위해 코드는 단일 함수 또는 작은 모듈 수준으로 유지하고, 실제 비밀값·실제 URL·접속 정보·외부 의존성은 넣지 않습니다.

| 허용 | 금지 |
| --- | --- |
| 취약한 암호 알고리즘, 안전하지 않은 API 사용, 검증 비활성화 등 정적 패턴 | 외부 IP·도메인·실제 서버를 겨냥하는 코드 |
| 사람이 읽을 수 있는 설명과 최소 코드 문자열 | 실제 자격 증명, 토큰, 개인정보, 고객 데이터 |
| Bandit으로 식별 가능한 비실행 예제 | 시스템 명령 실행, 네트워크 요청, 파일 파괴, 페이로드 전달 |
| 결정적 패치가 없을 때 `사람 검토 필요`로 남기는 설계 | 미검증 수정이나 공격 성공을 주장하는 결과 |

## 3. 블루팀 패치 연결

새 시나리오에 이미 지원되는 규칙이 포함되면 `security_ai_core.py`의 `patch_agent`가 해당 규칙을 처리합니다. 새로운 결정적 패치를 추가할 때는 의미가 명확하고 재스캔으로 검증 가능한 작은 변환만 추가해야 합니다. 여러 방식으로 해석될 수 있거나 프로그램의 동작을 임의로 바꿀 수 있는 수정은 자동화하지 말고 사람 검토 항목으로 남깁니다.

패치 규칙을 추가한 경우에는 다음 조건을 만족해야 합니다. 패치 전에는 Bandit이 목표 규칙을 찾아야 하고, 패치 후에는 같은 규칙이 사라져야 하며, 테스트는 다른 경고가 남을 가능성을 고려해 **총 탐지 수가 아니라 해결된 규칙 ID**를 확인해야 합니다.

## 4. 검증 절차

시나리오를 추가한 다음 전체 테스트를 실행하고, 로컬 대시보드에서 라운드 결과를 확인합니다. 대시보드는 저장소 코드 학습 지표, 해당 라운드의 모델-심판 일치도, 패치 전·후 심판 결과, 해결된 규칙과 남은 규칙을 함께 보여 줍니다.

```bash
cd -123
python3 -m unittest discover -s tests -v
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 `http://127.0.0.1:8000/dashboard`를 열고 **저장소로 훈련 실행**을 누릅니다. 이 요청은 저장소의 Python 파일을 읽고 AST로 함수 범위를 추출한 뒤, Bandit 정적 분석 결과로 자체 모델을 학습합니다. 제출된 코드나 저장소 소스는 실행되지 않으며 대시보드 보고서에 원본·패치 소스가 보관되지 않습니다.

## 5. 검토 체크리스트

새 시나리오는 병합 전에 안전 경계, 심판 탐지, 패치 정직성, 문서화의 네 가지 관점에서 확인해야 합니다. 실제 시스템 또는 개인·비밀 데이터를 사용하지 않았는지, Bandit이 목표 규칙을 식별하는지, 자동 패치를 주장한다면 재스캔으로 규칙별 해결이 검증되는지, 지원되지 않는 패치는 사람 검토로 표현하는지를 확인합니다. 마지막으로 `tests/test_red_blue_arena.py`에 해당 결과를 검증하는 테스트를 추가하여 이후 변경에서 안전성과 정직한 보고 원칙이 유지되도록 합니다.
