# 데이터 갱신 가이드

이 서비스가 쓰는 데이터가 어디서 오는지, 얼마나 자주 갱신되는지, API로 자동으로 받을 수 있는지 수동으로 받아야 하는지 정리한 문서입니다.

---

| 데이터 | 방식 | 갱신 주기 | 다음 갱신 시점 |
| --- | --- | --- | --- |
| 서울 생활인구 | API | 일 단위 누적 | 상시 |
| 서울 상권분석 (매출·점포·인구·소득) | API | 분기 | 분기 종료 후 약 3–4개월 |

## API로 받는 것 (자동화 가능)

### 서울 열린데이터광장

인증키 하나로 아래 전부 접근합니다. 환경변수 `SEOUL_API_KEY` 에 넣어 두세요.
발급: <https://data.seoul.go.kr> → 로그인 → 인증키 신청 (무료, 즉시 발급)

호출 형식은 모두 동일합니다.

```
http://openapi.seoul.go.kr:8088/{인증키}/xml/{서비스명}/{시작}/{끝}/
```

한 번에 최대 1,000행이므로 `list_total_count` 를 먼저 읽고 페이징해야 합니다.

| 서비스명 | 내용 | 주기 | 비고 |
| --- | --- | --- | --- |
| `SPOP_LOCAL_RESD_DONG` | 생활인구 (집계구·시간대별) | 일 | 약 3–4일 지연. 특정 날짜·시간을 골라 씁니다 |
| `VwsmTrdarSelngQq` | 상권 추정매출 | 분기 | 업종별 매출·객단가·시간대·요일·연령 |
| `VwsmTrdarStorQq` | 상권 점포 | 분기 | 업종별 점포 수·개업·폐업·프랜차이즈 |
| `VwsmTrdarRepopQq` | 상권 상주인구 | 분기 | |
| `VwsmTrdarWrcPopltnQq` | 상권 직장인구 | 분기 | |
| `VwsmSignguNcmCnsmpW` | 소비(소득소비-자치구) | 반기 | 자치구별 지출 구성비. 소득(월평균소득)은 서울시가 2026-05 원본 종료 → 미제공. 최신 분기 카테고리 집계가 깨지는 경우가 있어 `collect_income.py`가 자치구별 '완전한 분기'를 선별함 |
| `TbgisTrdarRelm` | 상권 영역·좌표 | 비정기 | 상권 코드와 XY 좌표 (EPSG:5181) |

**분기 데이터 주의점.** 상권분석 서비스의 분기 데이터는 해당 분기가 끝나고 **3–4개월 뒤**에 올라옵니다. 예를 들어 1분기(1–3월) 데이터는 6–7월쯤 나옵니다. 갱신 스크립트는 최신 분기 코드를 하드코딩하지 말고, `STDR_YYQU_CD` 의 최대값을 읽어서 쓰도록 되어 있어야 합니다.

## 수동으로 받아야 하는 것

API가 없거나 형식이 매번 달라서 사람이 확인해야 하는 것들입니다.

### 국세청 폐업 통계 — 연 1회

- 국세통계포털 <https://tasis.nts.go.kr> → 국세통계 → 사업자 현황
- 필요한 표: 시군구별 폐업 사업자 수, 폐업 사유별 사업자 수
- **전년도 확정치가 매년 상반기에 공표됩니다.** 잠정치가 먼저 나오는 경우가 있으니 확정치를 기다리는 편이 낫습니다.
- 엑셀로 받아서 자치구별 건수만 뽑으면 됩니다. 현재 값: 2022년, 2024년 두 시점을 써서 증감률을 계산합니다.

### 한국부동산원 상업용부동산 임대동향 — 분기

- 부동산통계정보 R-ONE <https://www.reb.or.kr/r-one> → 상업용부동산 임대동향조사
- 필요한 값: 서울 상권별 중대형 상가의 ㎡당 임대료, 공실률
- **분기 종료 후 약 1개월 뒤** 공표됩니다. 상권분석 데이터보다 빠릅니다.
- 상권 이름이 가끔 바뀝니다 (통합·분리). 코드의 자치구→상권 매핑이 깨지지 않았는지 확인해야 합니다.

### 통계청 소상공인실태조사 — 연 1회

- KOSIS <https://kosis.kr> 또는 통계청 보도자료
- 필요한 값: 자영업 평균 월매출, 평균 영업이익, 창업비용, 1년 생존율
- 벤치마크 비교선에만 쓰이므로 급하지 않습니다. 매년 한 번 확인하면 충분합니다.

## 갱신 순서

분기마다 하는 일:

```bash
export SEOUL_API_KEY=발급받은_키

# 1. API 데이터 수집
python backend/build_seoul_dataset.py     # 상권분석 (매출·점포·인구)
python backend/collect_subway.py          # 지하철 승하차
python backend/collect_parking.py         # 주차장
python backend/collect_livepop.py         # 생활인구

# 2. 수동 데이터 반영
#    부동산원 임대료를 받아 core.json 의 rentZones 갱신

# 3. 번들 재생성
python backend/build_bundle.py            # data-bundle.js 생성

# 4. 배포
#    frontend/data-bundle.js 만 교체하면 됩니다. index.html 은 그대로.
```

연 1회 추가로 하는 일:

- 국세청 폐업 통계 갱신 → `core.json` 의 `gu` (자치구별 y2022/y2024) 와 `reasons`
- 통계청 소상공인실태조사 갱신 → `core.json` 의 `bench`

## 갱신 후 확인할 것

- '방법' 화면의 기준 시점이 새 분기로 바뀌었는가
- 상권 이름이 바뀌어 자치구→상권 매핑에서 빠진 구가 없는가 (빠지면 서울 평균으로 폴백되며 화면에 표시됨)
- 새로 공표된 항목이 있는가 (예: 소득 데이터가 다시 나오면 빈 상태 화면이 자동으로 채워짐)
- 업종 목록이 바뀌었는가 (서울시가 업종 분류를 개편하는 경우가 있음)

### 자동 무결성 점검 (`backend/check_data.py`)

분기 갱신 후 특정 서비스의 카테고리 집계가 깨지는 일이 있다(예: 2026 1분기 소비-자치구에서
여가·문화가 소비의 96%로 나온 사례). 워크플로는 번들 재생성 뒤 `check_data.py`를 **비차단 리포트**로
실행해 이상치를 로그에 남긴다. 값을 고치지는 않고 검사·경고만 한다(정상 데이터를 함부로 버리지 않음).

- 로컬 점검: `python backend/check_data.py` — 비율합·범위·소비 구성 이상치 리포트
- CI 게이트: `python backend/check_data.py --strict` — FAIL 있으면 종료코드 1
- 소비는 이중 방어: 수집기(`collect_income.py`)가 자치구별 완전한 분기를 고르고, 화면(index/compare)도
  같은 기준으로 이상치면 '보정 중'으로 표시해 깨진 값이 노출되지 않게 한다
