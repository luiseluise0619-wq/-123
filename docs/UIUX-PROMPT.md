# UI/UX 재설계 지시 프롬프트

AI에게 이 서비스의 화면을 다시 만들게 할 때 그대로 붙여넣는 원고.
프로그램 소개 → 디자인 방향 → 절대 깨면 안 되는 것 순서다.
아래 `---` 사이를 통째로 복사해 쓴다.

---

## 이 프로그램이 무엇인가

**사장님인사이트** — 서울에서 가게를 낼 자리를 고르는 사람을 위한 상권 인텔리전스 웹서비스다.
예비 창업자와 소상공인이 쓴다. 회원가입은 없다.

핵심 질문은 하나다. **"내 업종으로 어디서 시작하면 기회가 있나?"**
상권을 분석해 주는 서비스가 아니라, **업종 × 입지의 시장 공백을 찾아 주는** 서비스다.
이 구분이 제품의 전부다. 지도·매출·유동인구·상권점수는 흔하다. 시장 공백이 우리 무기다.

### 화면 구성

| 화면 | 파일 | 하는 일 |
|---|---|---|
| 인텔리전스 (첫 화면) | `zone.html` | 업종을 고르면 수요는 있는데 그 업종 점포가 적은 상권을 랭킹으로 보여준다. 맞춤 탐색(`#fit`)에서 예산·중요 조건을 넣으면 순위를 다시 계산한다. 상권을 열면 진단(결론 → 변화 → 전망 → 요인 → 근거 → 다음 할 일). |
| 진단 | `mvp.html` | 지역·업종·평수·자금을 넣으면 손익분기와 예상 월 순이익을 계산한다. |
| 비교 | `compare.html` | 자치구·상권·임대료를 나란히 놓고 본다. |
| 건물 지도 | `building.html` | 카카오 실지도에 핀을 찍으면 그 자리 브리핑(주소·유동인구·가까운 역·반경 내 경쟁 점포). |
| 상담·데이터·방법 | `index.html#chat` `#data` | 데이터 근거로 답하는 상담, 쓰는 자료 12종, 계산식과 우리가 정한 가정. |
| 연도별 추이 | `trends.html` | 업종·자치구 시계열. |
| 소개 / 처리방침 | `about.html` `privacy.html` | |

### 무엇으로 계산하나

전부 **공개 통계**다. 개인을 식별하는 데이터는 쓰지 않는다.
서울시 상권분석서비스(추정매출·점포·개폐업·상권변화지표) · 서울 열린데이터광장(생활인구·상주인구·직장인구·소득소비)
· 국세청(폐업) · 한국부동산원(임대료·공실률) · 전국주차장정보 · 서울시 버스정류소 · 카카오 로컬 API.

서울 상권 **1,564곳**, 업종 **62개**를 다룬다.
기회점수 = 수요 45% + 희소성 35% + 점포당 매출 20% (가산식이라 기여도를 정확히 분해할 수 있다).

### 기술 제약 — 이걸 모르고 그리면 다 다시 해야 한다

- **정적 사이트다.** 빌드 도구·번들러·프레임워크가 없다. React·Vue·Next.js·Tailwind 전부 쓰지 않는다.
  HTML + CSS + 바닐라 JS로만 만든다. `index.html` 만 자체 템플릿 프레임워크(`support.js`)를 쓴다.
- **디자인 토큰은 `frontend/theme.css` 한 벌**이다. 색·타이포·간격·둥글기·그림자·버튼·칩·시트·상태를
  전부 여기서 정의하고 각 화면은 그 화면 고유 배치만 갖는다. 페이지마다 색을 새로 정의하지 않는다.
- **밝은/어두운 테마 3상태**를 지킨다. `:root`(밝음) → `@media (prefers-color-scheme: dark)` 안에
  `:root:not([data-theme="light"])` → `:root[data-theme="dark"]`. 어떤 색도 미디어 쿼리 안에서만
  처음 정의되면 안 된다.
- **차트 라이브러리를 넣지 않는다.** 지금 순수 SVG로 그린다. 그대로 간다.
- 카카오 지도 도형 색에는 CSS 변수를 쓸 수 없다(캔버스라 변수를 못 읽는다). 리터럴 16진수로 둔다.

## 이렇게 바꿔라

### 방향 — 토스 + 애플, 흰색 기반

**흰색과 여백이 기본이고, 색은 뜻이 있을 때만 쓴다.**

토스에서 가져올 것 — **정보 설계와 흐름**
- 한 화면에 질문 하나. 답하면 다음이 열린다. 한 번에 다 묻지 않는다.
- 결론을 맨 위에 문장으로 쓴다. 숫자를 늘어놓고 사용자가 해석하게 두지 않는다.
- 숫자를 만질 수 있게 한다. 조건을 바꾸면 결과가 그 자리에서 다시 계산된다.
- 다음 행동이 항상 하나 보인다. 분석을 보여주고 끝내지 않는다.

애플에서 가져올 것 — **여백과 타이포그래피**
- 구획을 선으로 나누지 말고 **여백으로** 나눈다. 테두리는 정말 필요한 자리에만.
- 카드를 남발하지 않는다. 카드 안의 카드는 금지.
- 큰 제목은 크게(clamp), 자간은 좁게(-0.03em 안팎), 행간은 촘촘하게(1.06~1.1).
- 한 화면에 큰 숫자는 **하나**. 여러 개를 크게 만들면 무엇이 중요한지 사라진다.
- 버튼은 알약형, 그림자는 최소, 움직임은 짧고(120~250ms) 감속 곡선으로.

우리 것 — **정직함이 디자인의 일부다**
- 실측 / 추정 / 미확인을 화면에서 눈으로 구분할 수 있어야 한다.
- 근거가 얇은 값에는 그 사실을 옆에 적는다. 감추지도, 그냥 내보내지도 않는다.

### 색

- 바탕은 흰색(`#FFFFFF`), 면은 아주 옅은 회색(`#F5F5F7`) 정도까지만.
- 글자는 3단계 회색조 하나로 위계를 만든다(진한 먹 / 보조 / 캡션).
- 포인트 색은 **한 개**. 링크와 주요 버튼에만 쓴다.
- 의미색(증가·감소·주의)은 그 뜻이 있을 때만. 장식으로 쓰지 않는다.
- 어두운 모드는 순수 검정(`#000000`) 바탕으로 간다.

### 구조 정리 — 첫 화면이 너무 많다

지금은 지역 게이트 → 히어로 → 또 히어로로 들어가는 문이 겹쳐 있다. 하나로 줄인다.

1. **`zone.html`(인텔리전스)이 첫 화면이다.** 사이트 루트가 여기로 온다.
2. `index.html`의 지역 선택 게이트와 진입 히어로를 없앤다. 서울을 기본으로 두고
   충북·충남은 작은 전환 컨트롤로만 남긴다.
3. 상단 메뉴에서 **상권 지도를 빼고 건물 지도와 상담을 올린다.**
4. 하단에서 **데이터·개인정보 처리방침 링크를 뺀다.**
   (처리방침은 이메일 수집 동의 문구에서 계속 열 수 있어야 한다 — 법적으로 필요하다.)

### 화면별 완료 기준

- **인텔리전스** — 업종을 고르는 순간 랭킹이 보인다. 결론 문장이 목록 1위와 같은 곳을 가리킨다.
  근거가 얇은 상권(점포 5곳 미만)은 기본 목록에서 빠지고 버튼으로 펼쳐진다.
- **맞춤 탐색** — 세 질문이 차례로 열린다. 조건을 바꾸면 순위가 실제로 바뀌고,
  어떤 비중으로 계산했는지 막대로 보인다.
- **진단(상권)** — 첫 화면에 결론 한 문장 + 큰 숫자 하나. 상세는 접혀 있다.
- **손익 진단** — 큰 숫자는 예상 월 순이익 하나. 조건 슬라이더가 즉시 반영된다.
- 모든 화면 — 390px에서 가로 스크롤이 없고, 밝은/어두운 양쪽에서 대비가 확보된다.

## 절대 깨지 말 것

1. **없는 값을 지어내지 않는다.** 데이터가 없으면 "데이터 없음"이라고 쓴다.
   실측·추정·가정·폴백을 화면과 주석에서 구분한다.
2. **API 키는 화면에 절대 노출하지 않는다.** 서버 함수(`frontend/api/*.js`) 안에만 둔다.
   AI 프록시의 origin-lock을 풀지 않는다.
3. **개인정보는 최소만 수집한다.** 지금 받는 것은 이메일·조회 지역·업종·리포트 종류·동의 여부뿐이다.
   항목을 늘리지 않는다.
4. **바꾼 화면은 실제 브라우저에서 확인한다.** 밝은/어두운 × 데스크톱/390px 모바일.
   콘솔 에러 0, 가로 스크롤 0을 확인하고 끝낸다.
5. **한 파일을 1,000줄 넘게 키우지 않는다.** 인수인계가 목적이라 읽히는 것이 우선이다.
