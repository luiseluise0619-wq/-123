# 공개 GitHub 취약 코드 코퍼스 학습 결과

AegisAI는 공개 GitHub 배포본에서 내려받은 VulDeePecker 코드 조각을 텍스트로만 읽어 자체 로컬 나이브 베이즈 모델을 학습했다. 데이터의 원본 코드는 가져오거나 실행하지 않았고, 학습 후 레드팀·블루팀의 로컬 교육 시나리오 우선순위에만 모델 확률을 사용했다. 취약점 탐지, 레드팀 점수, 블루팀 패치 성공은 계속해서 Bandit 심판의 재스캔 결과로 판정한다.

| 측정 항목 | 실제 결과 |
| --- | ---: |
| 원본 공개 코드 조각 | 61,638개 |
| 중복 제거 후 학습 문서 | 27,840개 |
| 취약 라벨 | 10,450개 |
| 비취약 라벨 | 17,390개 |
| 프로그램 그룹 | 1,419개 |
| 학습 분할 | 21,892개 |
| 그룹 홀드아웃 | 5,948개 |
| 홀드아웃 정확도 | 60.3% |
| 정밀도 | 50.0% |
| 재현율 | 89.0% |

평가는 프로그램 그룹을 기준으로 결정적 약 80/20 홀드아웃을 사용했다. 따라서 같은 그룹의 변형이 학습과 평가에 동시에 들어가지 않도록 했지만, 이 결과가 다른 언어·다른 프로젝트·실제 운영 코드에서의 성능을 보장하지는 않는다. 특히 해당 공개 코퍼스는 C/C++ 중심이므로 Python 기반 레드팀 교육 시나리오에서 모델 확률은 **참고용 우선순위 신호**일 뿐이다.

> 학습 모델이 높은 위험 확률을 반환해도 취약점 존재를 확정하지 않는다. AegisAI는 Bandit의 실제 정적 분석 결과를 심판으로 유지하며, 블루팀이 패치한 규칙이 재스캔에서 사라질 때만 해결로 기록한다.

## 대결 연결 방식

`POST /api/v1/training/red-blue` 요청에서 `training_corpus`를 `public-github-vulnerability`로 설정하면 공개 코퍼스로 학습한 모델이 로컬 레드팀·블루팀 대결의 위험도 우선순위를 산출한다. 대결 자체는 네트워크 대상, 실행 파일, 실제 익스플로잇, 외부 시스템 공격을 포함하지 않는다. 레드팀은 승인된 비실행 교육 시나리오를 제시하고, 블루팀은 결정적인 변환만 시도하며, 심판은 Bandit 재스캔으로 결과를 확인한다.

```json
{
  "rounds": 5,
  "training_corpus": "public-github-vulnerability",
  "retrain_model": true
}
```

대시보드의 **Training corpus** 선택에서 `공개 GitHub 취약 코드`를 고른 뒤 훈련을 실행해도 동일한 흐름으로 동작한다. 화면은 코퍼스 크기·라벨 분포·홀드아웃 지표와 각 라운드의 모델-심판 일치·패치 검증 결과를 표시한다.

## 출처

공개 코퍼스는 [VulDeePecker 배포 저장소](https://github.com/CGCL-codes/VulDeePecker)의 CWE-119 및 CWE-399 코드 조각 파일을 사용했다. 더 넓은 공개 CVE 수정 이력은 [CVEfixes](https://github.com/secureIT-project/CVEfixes)와 그 [Zenodo 배포본](https://doi.org/10.5281/zenodo.4476563)에서 제공하는 관계형 데이터베이스를 통해 후속 확장 대상으로 추적한다. 데이터 출처 비교와 안전 경계는 `docs/EXTERNAL_DATASET_SOURCES.md`에 정리되어 있다.
