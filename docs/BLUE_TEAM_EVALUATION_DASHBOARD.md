# CVEfixes 블루팀 평가 및 대응 대시보드

이 기능은 CVEfixes의 수정 전·후 메서드 쌍을 사용해 언어별 블루팀 모델의 탐지 정확도와 오탐률을 측정하고, 승인된 레드팀 교육 시나리오에 대한 방어 반응을 정적 분석으로 시뮬레이션한다. 모든 입력은 텍스트로만 읽으며, 원본 코드는 실행·자동 적용·외부 전송하지 않는다.

> 모델 확률은 우선순위 신호이며, 블루팀 패치의 성공은 정적 분석 재스캔이 실제로 규칙 해소를 확인할 때만 인정한다.

## 평가 항목

| 항목 | 정의 | 해석 |
| --- | --- | --- |
| 탐지 정확도 | 수정 전 취약 메서드와 수정 후 안전 메서드를 올바르게 분류한 비율 | 클래스 분포에 영향을 받으므로 단독으로 사용하지 않는다. |
| 정밀도 | 취약으로 예측한 메서드 중 실제 수정 전 메서드의 비율 | 낮으면 개발자 검토 부담이 커진다. |
| 재현율 | 수정 전 취약 메서드를 찾아낸 비율 | 낮으면 알려진 취약 패턴을 놓칠 수 있다. |
| 오탐률 | 수정 후 메서드(하드 네거티브)를 취약으로 잘못 예측한 비율 | 패치 후 안전한 코드에서의 경보 부담을 보여 준다. |
| 심판 검증 패치 | 레드팀 교육 시나리오에서 Blue-Team 변경 후 해당 규칙이 재스캔으로 사라진 횟수 | 자동 패치 성공의 유일한 확정 기준이다. |

CVEfixes 데이터 사전에서 `method_change.before_change`은 메서드가 취약한 수정 전 버전인지 나타낸다. 파이프라인은 같은 변경의 수정 후 메서드를 구조적으로 가까운 안전 예제, 즉 하드 네거티브로 사용한다.[1]

## CLI 평가

공식 CVEfixes SQL 덤프를 SQLite로 변환한 뒤 평가를 실행한다. 설치 안내에 제시된 변환 방식과 데이터베이스 구조를 사용한다.[2]

```bash
cd -123
python evaluate_cvefixes_blue.py \
  --db /absolute/path/to/CVEfixes.db \
  --minimum-recall 0.85 \
  --report reports/cvefixes_blue_evaluation.json
```

`--limit 1000`을 지정하면 초기 검증을 위해 최대 1,000개 패치 쌍만 평가할 수 있다. JSON 보고서는 언어별 임계값, 전체 탐지 지표, 수정 후 하드 네거티브 기반 오탐률, 승인 시나리오별 레드팀·블루팀·심판 상태를 포함한다. 원본 취약 코드와 패치 코드는 보고서에 저장하지 않는다.

## 웹 대시보드

백엔드를 실행한 뒤 `http://127.0.0.1:8000/blue-dashboard`를 연다. 변환한 공식 데이터베이스 파일을 프로젝트 상위의 `cvedata/` 디렉터리에 넣고 파일명을 입력한다. 예를 들어 `/home/ubuntu/cvedata/CVEfixes.db`는 화면의 `CVEfixes.db`로 지정한다.

| 화면 영역 | 표시 내용 |
| --- | --- |
| 요약 지표 | 평가한 패치 쌍 수, 탐지 정확도, 오탐률, 정밀도·재현율, 심판 검증 패치 수 |
| 언어별 성능 | 언어별 검증 세트 임계값과 정확도·재현율·오탐률 비교 막대 |
| 평가 해석 | 하드 네거티브, 최소 재현율 목표, 학습하지 않은 언어의 제외 상태 |
| 레드팀 대응 | 정적 분석 발견 규칙, 언어 모델 가용성, 블루팀 패치 시도, 사람 검토, 재스캔 검증 상태 |

대시보드의 평가는 Admin 또는 Security Lead 역할로만 시작할 수 있다. 데이터베이스 파일명은 `cvedata/` 아래의 `.db` 파일로 제한하며, 다른 경로 읽기와 원격 데이터베이스 접속은 허용하지 않는다.

## 새 레드팀 시나리오의 대응 해석

최근 추가한 `predictable-session-nonce` 시나리오는 Python의 예측 가능한 난수 패턴을 Bandit `B311`로 탐지한다. C 중심 CVEfixes 모델만 학습된 경우 대시보드는 Python 모델이 없다고 정직하게 표시하고, 정적 분석 심판은 계속 시나리오를 탐지한다. 블루팀이 의미를 보존하는 자동 패치를 보장할 수 없으면 사람 검토 필요 상태를 반환한다. 모델이 없을 때 추정 확률을 만들어 내지 않는 것이 언어별 모델 분리의 안전한 동작이다.

## 안전 경계

평가·대시보드·시뮬레이션은 정적 데이터 처리 전용이다. 실제 시스템 공격, 네트워크 스캔, 익스플로잇 실행, 외부 파일 업로드, 임의 패치 자동 적용은 포함하지 않는다. CVEfixes 기반 유사 패치 증거는 메타데이터만 제공하며, 실제 변경은 결정적 규칙이나 승인된 사람이 수행한 뒤 재스캔으로 검증해야 한다.
