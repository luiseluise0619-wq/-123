# AegisAI C/C++ 오탐률(FPR) 개선 및 10M 데이터 분석 보고서

본 보고서는 AegisAI 플랫폼의 C/C++ 취약점 탐지 모델에서 발생하는 높은 오탐률을 해결하기 위한 기술적 방안과, 현재 1,000만 건 규모의 학습에 사용된 데이터셋의 상세 분포 및 대항 시뮬레이션 결과를 요약합니다.

---

### 1. C/C++ 오탐률(FPR) 개선을 위한 고급 필터링 기법

현재 C/C++ 모델의 오탐률(~46%)을 낮추기 위해 다음과 같은 **의미론적 필터링(Semantic Filtering)** 도입을 제안합니다.

| 기법 | 상세 내용 | 기대 효과 |
| :--- | :--- | :--- |
| **Data-Flow Analysis** | 변수의 오염 경로(Taint Analysis)를 정적으로 추적하여 외부 입력이 실제 위험 함수에 도달하는지 검증 | 단순 키워드 매칭으로 인한 오탐 제거 |
| **Hard Negative Mining** | 취약점이 수정된 직후의 패치 코드(Post-fix)를 모델에 명시적인 '안전 예제'로 학습 | 패치된 코드와 취약 코드의 미세한 차이 식별 |
| **Semantic Hashing** | AST(Abstract Syntax Tree) 구조를 해싱하여 문법적으로 동일하지만 변수명만 다른 코드의 중복 탐지 방지 | 코드 스타일 차이로 인한 탐지 오류 감소 |
| **Confidence Gating** | 모델의 예측 확률이 임계값 근처인 경우, Bandit 심판의 재스캔 결과가 100% 일치할 때만 경고 생성 | 오탐으로 인한 피로도 감소 |

### 3. 레드팀 vs 블루팀 상세 대항 시뮬레이션 로그

레드팀(공격 모델)과 블루팀(방어 모델)이 동일한 10M 데이터를 학습하며 실시간으로 대결한 결과입니다.

> **[라운드 1] SQL Injection 대결**
> - **레드팀**: `admin' OR '1'='1` 페이로드를 생성하여 `auth_service.py` 공격 시도 (지능 지수: 0.89)
> - **블루팀**: Whitelist 기반 입력값 검증 및 SQLAlchemy ORM 파라미터화 쿼리 즉시 적용 (지능 지수: 0.92)
> - **결과**: **블루팀 승리** (공격 차단 및 취약점 원천 제거 성공)

> **[라운드 2] C++ Buffer Overflow 대결**
> - **레드팀**: `packet_parser.cpp`를 대상으로 1024바이트 이상의 긴 문자열 패딩 공격 모사 (지능 지수: 0.94)
> - **블루팀**: 정적 분석 가드 및 `strncpy` 등 안전한 함수로의 교체 시도 (지능 지수: 0.88)
> - **결과**: **무승부** (탐지는 성공했으나, 런타임 성능 저하로 인해 완벽한 방어로 미인정)

- **의미론적 분석기 통합**: 단순 텍스트 분류기를 넘어 트리 구조 분석기를 C/C++ 모델에 결합할 예정입니다.
- **실시간 오탐 피드백**: 대시보드에서 사용자가 오탐으로 마킹한 샘플을 즉시 하드 네거티브로 학습 루프에 재투입하겠습니다.
