# MYSBIZON DESIGN GRAMMAR v1.0 적용 기록

## 조사 범위

- `frontend/screens` 화면 조각 19개와 `frontend/logic` 화면 로직 24개
- 공개 홈, 상권 찾기, 지도 정밀분석, 후보 비교, 손익 계산, 창업 준비, 리포트, 통합시세, 설정, AI 도우미
- 관리자 로그인·표·CSV 화면과 PC·태블릿·모바일 레이아웃
- 색, 글자, 간격, radius, shadow, motion의 하드코딩 및 공통 토큰 사용 여부

기존 화면은 `#087F6B`, `#191F28`, `#4E5968`, 20·24px 카드 radius, 12~20px의 서로 다른 카드 padding, 10~40px의 임의 gap이 섞여 있었습니다. 일반 카드와 CTA에도 그림자가 남아 있었고, 홈 첫 진입 동작은 2.5~2.9초가 걸렸습니다. 같은 역할의 숫자가 22~38px 사이에서 달라 화면별 위계가 일정하지 않았습니다.

## 기준 토큰

| 종류 | 토큰 |
|---|---|
| 브랜드 | Bizon Mint `#32B99A`, Hover `#299C83` |
| 중립 | Ink `#171A19`, Secondary `#707672`, Warm Paper `#F6F6F2`, Surface `#FFFFFF`, Border `#E5E7E4` |
| 상태 | Warning `#D8963E`, Error `#D95B5B` |
| 간격 | `4, 8, 12, 16, 24, 32, 48, 72px` |

| 글꼴 | 자체 호스팅 Wanted Sans Variable `400–1000` |

모든 값은 `_shell-head.html`의 전역 토큰과 `logic/design.js`의 공통 컴포넌트에 모았습니다. 기존 짧은 변수 이름은 동작 호환을 위해 새 토큰의 별칭으로 유지했습니다.

## 적용 내용

- 일반 카드: 흰 배경, 1px border, 16px radius, PC 24px·모바일 20px padding, 그림자 없음
- 버튼·입력: 12px radius, 160~220ms 전환, CTA 외 민트 면 사용 축소
- 제목: Hero 42/54, Page 32/44, Section 24/34, Card 18/28
- 숫자: 주요 수치 40/44, 보조 수치 26/32, tabular number 적용
- 본문: 16/26, 보조 14/22, 설명 13/20
- 페이지: PC 최대 1280px·32px padding, 태블릿 24px, 모바일 20px
- 주요 section: PC 72px, 모바일 48px 간격
- 홈: 긴 대기 연출을 220~280ms의 짧은 등장으로 변경하고 검색 상자의 상시 그림자를 제거
- 드롭다운·설정·AI 패널·지도 안내: 실제로 떠 있는 면에만 shadow 유지
- 지도 결과 패널: 기본 카드는 border로만 구분하고 선택한 핀과 현재 상태에만 민트 사용
- 관리자: 공개 화면과 같은 글꼴·색·간격·radius를 적용하고 모바일 표는 가로 스크롤 유지
- 이모지: 업종 빠른 선택과 최근 목록에서 제거해 텍스트 위계를 우선

## 기능 보존

업종·지역 검색, 지도 한 지점 선택, 500m 경쟁업체 조회, 후보 2~5곳 비교, 손익 계산, 체크리스트, 리포트, 시세, 고객 데이터와 관리자 인증 흐름은 유지했습니다. 디자인 변경은 계산식과 데이터 원본을 바꾸지 않습니다.

## 검증 기준

- 디자인 토큰과 자체 호스팅 폰트를 자동 테스트로 고정
- 생성 HTML·번들 일치, 데이터 구조, 배포 체크섬 확인
- 390px 모바일, 834px 태블릿, 1280px PC에서 가로 넘침과 핵심 화면 확인
- 관리자 1차 Basic 인증과 2차 키·새로고침 세션을 회귀 테스트로 확인
