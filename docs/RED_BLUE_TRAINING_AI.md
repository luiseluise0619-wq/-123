# AegisAI 레드팀·블루팀 훈련 AI 설계

AegisAI의 레드팀·블루팀 모드는 실제 시스템을 공격하는 기능이 아니라, **통제된 로컬 코드 문자열을 대상으로 하는 방어 훈련 환경**이다. 레드팀은 사전에 승인된 취약 패턴 카탈로그에서 학습용 시나리오를 선택하고, 블루팀은 결정적으로 안전성이 검증 가능한 패치만 적용한다. 심판은 Bandit 정적 분석 결과만을 판정 근거로 사용한다.

> 이 기능의 “자체 AI”는 외부 생성형 AI 서비스가 아니라, Bandit이 라벨링한 로컬 학습 데이터로 학습하는 자체 구현 토큰 기반 나이브 베이즈 취약성 분류기다. 분류기의 확률은 우선순위 보조 신호일 뿐이며, 취약점 존재·패치 성공·점수는 반드시 심판의 실제 재스캔으로만 확정한다.

| 역할 | 책임 | 허용 범위 | 금지 범위 |
| --- | --- | --- | --- |
| 레드팀 | 승인된 교육용 코드 시나리오 선택 | 약한 해시, `shell=True` 등 비실행 코드 문자열 | 네트워크 요청, 실제 익스플로잇, 임의 페이로드 생성 |
| 블루팀 | 결정적 수정 제안·적용 | 알려진 규칙에 대한 코드 변환 | 미검증 일반 패치 성공 주장 |
| 심판 | 전·후 정적 분석과 점수 산정 | Bandit 재스캔, 규칙별 해결 여부 비교 | 레드·블루팀의 자기보고만으로 판정 |
| 자체 모델 | 위험도 우선순위 확률 산출 | 로컬 토큰 특성 학습·JSON 모델 저장 | 사실 판정 또는 자동 패치 승인 |

## 학습 및 평가 흐름

1. 레드팀 시나리오와 정상 코드 표본을 준비한다.
2. 심판이 각 표본을 Bandit으로 분석해 실제 라벨을 생성한다.
3. 자체 나이브 베이즈 분류기는 심판 라벨과 코드 토큰만 사용해 학습하고, 모델 구조·표본 수·라벨 출처를 함께 저장한다.
4. 레드팀이 선택한 시나리오가 심판에게서 탐지되면 레드팀의 유효 시나리오로 기록한다.
5. 블루팀은 지원하는 규칙만 패치한 뒤 심판이 같은 규칙의 탐지 결과가 사라졌는지 재스캔한다.
6. 점수는 심판의 전·후 결과에서 계산하며, 패치가 불가능하거나 검증되지 않으면 성공으로 기록하지 않는다.

| 점수 | 부여 조건 |
| --- | --- |
| 레드팀 점수 | 심판이 교육용 시나리오에서 실제 탐지 결과를 반환한 경우 |
| 블루팀 점수 | 블루팀이 수정한 특정 규칙이 심판의 재스캔에서 사라진 경우 |
| 심판 검증 수 | 전·후 결과가 비교되어 규칙별 해결 여부가 객관적으로 확인된 경우 |

## API 범위

`POST /api/v1/training/red-blue`는 1~16회의 로컬 훈련 라운드를 실행한다. 요청은 선택적으로 `retrain_model`을 받을 수 있으며, 응답에는 모델 메타데이터, 시나리오 식별자, 심판의 전·후 탐지 수, 검증된 규칙, 점수만 포함한다. 원본 코드·패치 코드는 응답이나 감사 보고서에 보존하지 않는다.

이 API는 기존의 로컬 개발용 요청 컨텍스트 헤더를 사용한다. 공개 배포 전에는 반드시 검증된 인증·권한부여·속도 제한·영속 저장소 암호화를 별도로 구현해야 한다.
